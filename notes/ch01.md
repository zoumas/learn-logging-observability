## 1.2 Linko Overview

CLI lesson: clone `bootdotdev/linko-starter`, run `go run .`, and submit the
check with Linko serving on `http://localhost:8899`.

Notes:

- This repository is the starter with its history kept. `upstream` points at
  `bootdotdev/linko-starter`, so a fix to the starter can be merged in later.
- The starter keeps the module path `boot.dev/linko` (it reverted a rename in
  `3557170`). Renaming it would rewrite every internal import for no gain.
- The course says the starter has deliberate bugs and oddities, to be found
  with observability later. Do not fix them early.
- Measured on `36bba29`: `go build -race`, run, `POST /admin/shutdown`. The race
  detector reports a data race on `serverErr` in `main.go`. The server
  goroutine writes it (`serverErr = s.start()`) and `run` reads it after
  `<-ctx.Done()` with no synchronization between them. `Shutdown` does not
  wait for the goroutine that called `Serve` to return, so the read can come
  before the write, and nothing orders them. The usual fix is a buffered
  `chan error` of size 1 that the goroutine sends on and `run` receives from.
  Left as is: it may be one of the deliberate bugs.
- Measured: `golangci-lint run` reports 6 errcheck issues on the starter. They
  are starter code, not findings.
- Production note: the handler for `POST /admin/shutdown` is open to anyone
  unless `ENV=production`. A kill switch keyed on an environment variable
  fails open when the variable is missing or misspelled. On a device or a
  shared host, bind admin endpoints to localhost or a separate listener instead.
